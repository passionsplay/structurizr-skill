## Observations

- Every baseline failure but one had `validate_calls=0`: the agent wrote DSL and declared victory. The one exception validated 12 times and still could not converge without the DSL rules. This repeats the k=1 finding: the skill's value for this model is the validate loop plus the identifier and ordering rules.
- Where both conditions pass, the skill is still 2-5x faster and 3-10x cheaper (`component-store`, `export-mermaid`), because the baseline explores Structurizr's CLI by trial and error.
- `fix-forward-reference` does not discriminate (both 3/3, baseline slightly faster). Make it harder or retire it.
- Wall time was about 1h45m, sequential. Two drivers: baseline trials that run to or near the 600s timeout, and each `structurizr.sh validate` call starting a fresh JVM container, which took about 28s per call on this Intel Mac. Graders call it too. Parallel trials (`-j`) and a warm validator (`docker exec` into a running container) are the obvious fixes.
